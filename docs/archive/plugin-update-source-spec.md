- 原始范围：Obsidian 插件自身的版本检查和 Release 文件下载

> 下文保留当时的设计与实施记录，不是当前功能说明或开发要求。其中“当前”“现有”、旧文件名、测试数量及验证结果均属于原始记录，不能作为现版本能力或验证证据。现版本只读取官方仓库根清单并提示用户通过 Obsidian 社区插件市场更新，不再执行本文的客户端下载安装流程。

## 1. 目标与现状

让插件更新支持与服务端一致的三种源：官方直连、默认加速、自定义 HTTPS 加速前缀。所选源同时用于 GitHub API 版本检查与 Release 文件下载，避免只能下载文件、无法检查版本的问题。

当前插件直接请求 GitHub，仓库由 `updateRepo` 指定，默认 `helantianshen/oss-sync`。检查版本优先读取 Release 中的 `manifest.json`，失败时退回 Release 标签；安装时下载 `main.js`、`manifest.json`、`styles.css` 并验证大小和 SHA-256，然后替换文件并重载插件。

服务端参考实现：[地址转换](../../internal/update/download_source.go)、[API 请求选源](../../internal/update/github.go)、[管理界面](../../internal/webui/templates/admin_system.html)。当前 dev/prod YAML 均配置 `update.download_source: "proxy"`；这不等于后端所有缺省配置都自动选择代理。

## 2. 范围边界

本次包含插件设置、配置持久化与兼容、更新请求地址转换、交互状态和中英文文案。

不修改服务端配置或 API，不让服务端代转插件请求，不自动同步服务端选源，不新增代理可用性探测、镜像列表、自动切源、GitHub Token 配置或发布签名机制。保留现有版本比较、安装前重新检查、三文件替换与回滚流程。

权限和触发方式保持实际既有行为：登录用户可手动检查和更新，管理员在启动初始化后自动检查并提示；自动检查不执行安装。不因现有“仅管理员可更新插件”的过时注释而收紧权限。

## 3. 用户设置流程

入口：Obsidian 设置 → OSS Sync → 插件更新。

按以下顺序展示：

| 控件 | 内容及行为 |
| --- | --- |
| GitHub 仓库 | 保留现有输入，默认 `helantianshen/oss-sync` |
| 更新源 | 下拉选项：默认加速、官方直连、自定义加速 |
| 加速前缀 | 仅选择自定义加速时显示；占位示例 `https://mirror.example.com/` |
| 版本状态与操作 | 当前版本、检查更新，以及检查成功后出现的更新插件按钮 |

默认加速说明明确展示 `https://gh-proxy.com/`。自定义输入说明为：“填写 HTTPS 加速地址前缀，不要填写仓库地址；加速服务需同时支持 GitHub API 和 Release 文件下载。”示例域名仅用于解释格式，不是可用服务推荐。

选择与输入通过现有 `saveSettings()` 自动保存，无新增保存按钮。输入期间允许保存未完成的草稿，但自定义模式下必须通过校验后才能发起请求。字段失焦或点击检查时显示具体校验错误；无效配置不影响同步等其他插件功能。

切换至直连或默认加速时隐藏并保留自定义前缀，非自定义模式不验证、不使用该草稿。重新打开设置和重启插件均保留选择。配置归属于当前 Vault 的插件设置，各设备/实例独立设置，不从 OSS 服务端读取。

## 4. 配置模型与兼容

在 `OSSSettings` 中新增：

| 字段 | 类型 | 默认值 |
| --- | --- | --- |
| `updateDownloadSource` | `"official" \| "proxy" \| "custom"` | `"proxy"` |
| `updateDownloadProxy` | `string` | `""` |

保留 `updateRepo`。三个字段与其余插件设置通过既有 `loadData()` / `saveData()` 机制读写，不新增配置文件，不覆盖令牌或其他设置。

兼容规则：

1. 新安装和旧配置缺少源字段时均采用默认加速。这会使旧用户升级后从直连变为默认代理，是本方案明确提出的行为变化。
2. 运行时仍校验持久化数据类型；缺失、非字符串、空白或未知源值归一为 `proxy`，有效源值去掉首尾空格。
3. 前缀缺失或非字符串时归一为空字符串；字符串去掉首尾空格。自定义模式下空前缀报错，不回退到其他源。
4. 切换模式不清空前缀；无效自定义草稿不能导致插件加载失败。
5. 默认值可以在加载时内存补齐，随后由正常保存持久化，不为该变更新增启动写盘要求。

## 5. 地址生成与校验

在更新模块内提供纯函数统一处理地址，不在设置 UI、版本检查和文件下载中分别拼接。

| 源 | 目标地址 |
| --- | --- |
| `official` | 原始 GitHub URL |
| `proxy` | `https://gh-proxy.com/` + 原始 GitHub URL |
| `custom` | 规范化的自定义前缀 + 原始 GitHub URL |

自定义前缀规则与服务端的语义保持一致：

- 去掉首尾空格后长度不超过 1024 个字符。
- 必须是包含有效主机的绝对 HTTPS URL。
- 不允许用户名、密码、查询参数或 fragment；包括只有 `?` 或 `#` 的空标记也拒绝。
- 允许端口和路径前缀，例如 `https://mirror.example.com:8443/github/`。
- 去掉末尾多余 `/` 后补一个 `/`；不对整个原始 GitHub URL 做百分号编码，也不使用会丢失路径前缀的相对 URL 合并。
- 拒绝内部空白、控制字符、反斜杠等可能被浏览器 URL 解析器静默改写的输入；无需复现 Go 与 JavaScript 对畸形 URL 的差异。

以 `https://mirror.example.com/` 为例，实际请求如下：

```text
https://mirror.example.com/https://api.github.com/repos/helantianshen/oss-sync/releases/latest
https://mirror.example.com/https://github.com/helantianshen/oss-sync/releases/download/<tag>/main.js
```

统一覆盖以下请求：latest-release API、检查版本时的 `manifest.json`、安装时的三个文件。Release 返回的原始 `browser_download_url` 仍先执行现有 HTTPS 与 GitHub 主机校验，通过后才转换为代理请求地址；不要求转换后的地址仍属于 `github.com`。

保留资产唯一性、大小上限、实际长度和 SHA-256 校验。代理请求不附带 OSS 登录令牌。错误信息不得原样回显含凭据的非法输入。

## 6. 一次操作内的一致性

每次检查或安装开始时捕获不可变配置快照，包含仓库、源与前缀；该次操作的全部请求使用同一快照。

设置界面的状态处理：

1. 仓库、源或前缀发生变化后，清除已发现版本和安装按钮，提示重新检查。
2. 使用请求序号或配置代次标记，丢弃旧请求返回的 UI 结果；旧结果不能重新显示安装按钮，也不能覆盖新请求的忙碌状态。
3. 检查进行时禁用重复检查按钮，但允许修改配置；修改后的检查应在前一次检查结束后重新发起。
4. 安装进行时禁用本节配置项和检查/安装按钮，同时在执行入口拦截重复安装，防止重绘设置页绕过按钮状态。
5. 安装仍重新查询最新 Release，再使用该次返回的 Release 下载三个文件；不新增候选版本锁定协议。若检查和安装之间发布了更新版本，可能安装重新检查得到的版本，与既有行为一致。
6. 自动检查也捕获配置快照；配置变化后忽略其旧版本提示。其原有静默失败行为保持不变。

自定义配置必须在首次请求之前校验，不能让配置错误被 manifest 下载的容错路径吞掉。

## 7. 错误与信任边界

手动检查或安装失败时，使用现有状态区域/Notice 展示失败阶段、所选源及可理解原因；配置错误在输入项附近展示。提供中英文文案。网络错误、限流或代理不可用不触发隐式直连、重试其他源或修改已保存选择。

manifest 缺失、下载失败或解析失败时仍可以按现有规则用 Release 标签判断版本；安装阶段仍要求三个资产均可下载且校验通过。因此“发现新版本”不承诺可成功安装。

API 元数据和资产都经过代理时，SHA-256 校验可以发现内容与元数据不匹配，但不能证明代理没有同时替换二者。本次维持现有校验能力，不将其描述为独立发布者签名验证。默认代理的可用性和对 GitHub API 的支持需实测，源码配置不构成可用性保证。

## 9. 验收标准

| 场景 | 预期 |
| --- | --- |
| 新安装、旧配置缺字段 | 默认加速，仓库和其他设置保留 |
| 未知源值或错误字段类型 | 按兼容规则归一化，插件可正常加载 |
| 官方直连 | API 和所有文件请求均保持原始地址 |
| 默认加速 | API 和所有文件请求均使用固定默认前缀 |
| 自定义带路径/端口/多余尾斜杠 | 正确保留路径和端口，拼接边界只有一个 `/` |
| 空值、HTTP、无主机、凭据、查询、fragment、超长或畸形前缀 | 自定义模式阻止请求并提示；其他模式忽略草稿 |
| 切源后重启、重新打开设置 | 选择和自定义草稿仍在 |
| 检查中修改配置 | 旧响应不恢复更新按钮，重新检查使用新配置 |
| 安装中重复点击或重开设置页 | 不启动第二次安装，不混用不同源 |
| 自动检查 | 使用配置源，仅提示，配置变化后旧提示被忽略 |
| 代理失败 | 显示手动操作错误，不自动直连；自动检查保持静默 |
| 资产缺失、重复、超限、大小不符、digest 缺失或不符 | 保留现有拒绝行为 |
| 原始资产 URL 非 GitHub HTTPS | 拼接代理前即拒绝 |
| 文件替换或重载失败 | 现有回滚行为不回归 |
| 登录普通用户与管理员 | 保留现有手动入口和自动检查差异 |
| 中文和英文界面 | 控件、提示、错误完整且无缺失键 |
